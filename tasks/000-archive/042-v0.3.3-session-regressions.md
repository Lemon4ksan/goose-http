# 042: Stalls and extra instructions in the v0.3.3 session

Status: done

Two results from the 2026-10-15 Goose-only session (goose-rest's `bench/all.sh`, code as
`v0.3.3`, Goose `v2026.1`, the benchmark desktop under WSL2) need a cause: the emulated
ring keeps connections waiting for seconds on 64 KB files with 1 worker, and epoll's
plaintext costs about 20 more user instructions per request than on 2026-10-14
([results](../docs/results.md#2026-10-15-v033-goose-builds-only)). goose-rest's task 040
covers its own gaps from the same session.

## 1. The emulated ring stalls connections at 64 KB, 1 worker

`SERVERS="goose goose-uring goose-uring-epoll" bench/files.sh`, wrk with 8 threads and 64
connections on CPUs 4-15, 3 runs of 10 s. wrk's latency, average, standard deviation,
and maximum:

| Server, 64 KB, 1 worker | Run 1 | Run 2 | Run 3 |
|---|---:|---:|---:|
| Emulated ring | 74 ms, 304 ms, 3.76 s | 172 ms, 721 ms, 5.50 s, 22 timeouts | 261 ms, 728 ms, 4.61 s |
| io_uring | 2.07 ms, 0.28 ms, 4.29 ms | 2.11 ms, 0.33 ms, 4.97 ms | 2.10 ms, 0.28 ms, 4.38 ms |
| epoll | 1.93 ms, 0.22 ms, 9.74 ms | 1.94 ms, 0.16 ms, 3.10 ms | 2.11 ms, 1.72 ms, 45.9 ms |

Every run stalls some connections, not only the one with timeouts: the timeouts are
requests that waited past wrk's `--timeout 8`. The other cells of the emulated ring
stay under 75 ms at the maximum, 4 KB and 1 MB with 1 worker and every size with 4. Its
lead at 64 KB with 1 worker, 2.68 GB/s against epoll's 2.15, comes from serving some
connections while others wait, so the rate can't be read as a win. The 2026-10-14
session didn't run the emulated ring, so there is no earlier cell to compare.

- [x] Reproduce the stall: one 10 s run of the cell peaked at 3.45 s, 40.3 K files a
      second (2026-10-16).
- [x] Find where a starved connection waits, fix it, and rerun the cell. `ur_wait` in
      `shim/ring_epoll.c` returned as soon as its queued sockets made a completion,
      without `epoll_wait`, so a socket waiting for an edge waited until a call made
      none. It now collects events on every call, with a timeout of 0 when it has
      completions. One run per size with 1 worker: 4 KB 72.7 K/s, peak 25.8 ms; 64 KB
      43.6 K/s, peak 2.3 ms; 1 MB 12.3 K/s, peak 9.0 ms. `scripts/test.sh` passes.
- [x] Correct the static-files note in `docs/results.md`.

## 2. Epoll's plaintext, about 20 more instructions per request

`bench/instructions.sh goose goose-uring` as root, one worker on CPU 0, 3 runs. Epoll's
user instructions per request rose from 1,529-1,538 (median 1,533) to 1,548-1,566
(median 1,555), 1.4%, beyond the earlier range; cycles rose about 1.8% on epoll and 1.9%
on io_uring. The code (`v0.3.1` to `v0.3.3`) and the compiler (`46356c2` to `v2026.1`)
both changed between the sessions.

- [x] Count `v0.3.1` and `v0.3.3` with the same compiler, to tell the code's share from

      `bench/instructions.sh goose-v031 goose-head`, 3 interleaved runs (2026-10-16):
      `v0.3.1` 1,532-1,539 user instructions per request, `main` at `1c53fda1`
      1,538-1,550; cycles 2,068-2,084 against 2,051-2,080. `v0.3.1` counts the same
