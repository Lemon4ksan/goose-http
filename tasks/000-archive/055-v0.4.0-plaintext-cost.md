# 055: v0.4.0's plaintext cost

Status: done (found 2026-10-19, fixed 2026-10-20)

The nightly session of 2026-10-19 measured `v0.4.0` (`6512e790`, Goose `f114b5a`)
against the session of 2026-10-18 (`v0.3.7`, Goose `v2026.2`), with the same
`key.txt`. Plaintext pipelined 16 deep lost 9-11% of its rate on the epoll loop in five
of six cells, and 3.5-8.5% on io_uring; JSON lost 0.4-7%, mostly within the 5% that
sessions drift. The epoll server's peak RSS grew by 2.4 MB in every cell.

`bench/instructions.sh` (one worker on CPU 0, plaintext pipelined 16 deep, 256
connections; 3 runs) counted, in user instructions per request:

| Build | epoll | io_uring |
|---|---:|---:|
| `v0.3.7`, Goose `v2026.2` (2026-10-18) | 1,598-1,604 | 1,634-1,653 |
| `v0.3.7`, Goose `f114b5a` | 1,596-1,609 | 1,644-1,663 |
| `v0.4.0`, Goose `f114b5a` | 1,760-1,778 | 1,792-1,812 |

The compiler isn't the cause. A bisect of `main`'s first parents, one run per step
with Goose `f114b5a`, found two commits:

- **Instructions: `1bc944a3`**, which added WebSocket: 1,613 → 1,751 on epoll, 1,631 →
  1,799 on io_uring. The benchmark server's `handle` gained `else if st.route == WS {
  http::ws_read(...) }`, inlined into the handler, and `Transfer` gained `ws:
  http::WebSocket { limit: 1 << 25, .. }`, two `Gather`s and its fields, set up for
  every request. Without the `ws_read` branch, epoll counted 1,634; without the field
  as well, 1,612. So the inlined branch costs about 117 instructions per request on a
  path that never reaches it, and the field about 22. Later commits up to `v0.4.0`
  add about 20 more, not yet split.
- **Memory: `1012e705`**, which serves TLS in the epoll loop: the epoll server links
  `libssl` and `libcrypto` (none before), whose pages make the 2.4 MB, with
  instructions unchanged (1,613 → 1,622). The io_uring server imports no TLS and
  didn't grow.

## Ideas

- Keep the WebSocket's frame loop out of the inlined handler: `ws_read` in a function
  the handler calls but that isn't inlined, or the upgraded connection served by a
  handler of its own, as an upgrade switches the stream. Check what Goose inlines and
  why a branch never taken costs 117 instructions: the generated C of `handle` before
  and after.
- Keep the WebSocket state out of `Transfer`: an index into a pool taken at the
  upgrade, so a request that never upgrades sets up 8 bytes, not the struct.
- Serve TLS from a binary of its own, or load OpenSSL only when `Config.tls` is set, so
  the plaintext server doesn't map it.
- Split the remaining ~20 instructions between `1bc944a3` and `v0.4.0`.

## What the fixes measured

`bench/instructions.sh` on `main` at `251b1214` with Goose `f114b5a`, in a clone on
WSL's filesystem, 2 runs per step (3 for the last), user instructions per request and
peak RSS (2026-10-20). Runs on one build varied by up to 3% this session, more than the
1% of earlier ones.

| Build | epoll | io_uring | epoll peak RSS |
|---|---:|---:|---:|
| `main` | 1,783-1,816 | 1,717-1,766 | 6.0 MB |
| `ws_read` in a function of the server's | 1,625-1,644 | 1,670 | 6.0 MB |
| and the WebSocket out of `Transfer` | 1,611-1,622 | 1,647-1,654 | 6.0 MB |
| and the epoll server without TLS (3 runs) | 1,609-1,610 | 1,648-1,661 | 3.8 MB |
| `v0.3.7` (above) | 1,596-1,609 | 1,644-1,663 | 3.4-3.6 MB |

- **The 117 instructions.** `ws_read` stayed a C function of its own: Goose
  specializes a block-taking call into one, and gcc's inlining of a function called
  once isn't it (the same C built with `-fno-inline-functions-called-once` counted the
  same, 1,744-1,784). What changed is Goose's own inlining of the loop's nested `call`,
  which runs the handler: with the call that takes a block in the inlined `handle`, the
  generated C of the epoll server held 4 copies of `http::call` and 26 calls of them,
  115,000 lines; without it, 20 copies and 88 calls, 244,000 lines, and 1,616-1,645
  instructions. Calling `ws_read` from a function of the server's, `echo_frames`,
  restores the second shape. Which of Goose's inlining rules the block trips isn't
  traced.
- **The WebSocket's state.** `x.state = fresh` copies the whole `Transfer` at each
  request. `Transfer` now keeps an index, `ws: i64 = -1`, into a pool each worker owns
  (`sockets`, with a free list), taken at the upgrade and given back at `CLOSED`. The
  free list never shrinks: a `pop` from it doesn't compile, since the loops hold
  references Goose can't tell from one into a global `i64[>..]` (spec §5.1).
- **OpenSSL.** libcrypto (1,708 KB), libssl (308 KB), and their libz and libzstd
  (248 KB) were the 2.4 MB. `server/server_epoll.goose` now serves no TLS, and
  `server/server_tls.goose` (`TLS=1` in `scripts/build.sh`) is the epoll server with
  its TLS listener. HttpArena's image holds both and starts the TLS build only when
  HttpArena mounts a certificate, and `scripts/test.sh` tests the epoll loop with the
  TLS build ([decision](../../docs/decisions.md#the-benchmark-servers-tls-is-a-build-of-its-own)).

The ~20 instructions between `1bc944a3` and `v0.4.0` are gone with the fixes, so they
weren't split. `scripts/test.sh` passed with all three, on WSL's filesystem.
